模型价格估算

按 OpenRouter 上同名模型的价格，把每条请求的 token 折算成人民币，供面板的「OpenRouter 价估算」列与「API 等价花费」卡片使用。OpenRouter 的模型级价取的是 top provider 的价，多 provider 模型通常接近最低档，因此这是参考价，不等于 WorkBuddy 官方价或结算价。默认开启；关闭后不再向 OpenRouter 取价，也不再折算任何金额，相关列、卡片与取价控件一并隐藏（只留这个开关）。重新打开会补算关闭期间的请求：那段请求按之后第一次取到的价折算并标 *，所以关掉再打开不会丢数。
价估算已关闭：不再取价、不再折算金额，价格列与「API 等价花费」卡片一并隐藏；重新打开后会补算关闭期间的请求。

定价刷新

网关每隔这段时间去 OpenRouter 取一次价：每个模型每份不同的价格存成一条定价策略（内容相同就复用同一条，不重复写），并声明「现在生效的是哪一条」。每条请求按它发生时生效的那一条计价，所以之后调价不会改写之前的数字；请求只记它引用的是哪条策略，不内嵌整份价格。取价时还没有价的模型，用之后第一次取到的价补算并标 *。没人引用、又已经不作数的策略会被清掉（每个模型至少留一条，刚取到的那批不动）。取价间隔以分钟计，默认 5 分钟；填 0 表示不自动刷新（仍可用「立即取价」手动取一次）。
取价输入 = 内置目录 ∪ 网关实时目录里新增的模型，上游新上架的名字无需改代码就会进入下一轮取价；两次取价之间就被调用的新模型，第一笔请求即按内存里的目录按需补价。名字带渠道后缀（如 -lkeap）的模型默认按变体后缀继承向基准模型取价（要求唯一命中，命不中照旧显示未定价）；关掉开关即恢复「只有覆盖表与同名匹配才定价」。
刷新间隔（分钟）

国际版每日活跃打卡

一次打卡 = 一个预算 + 一个候选模型序列：按顺序换模型重试，预算用完必给结论。
① 时段
留空 = 每天随机两个时间、间隔 12 小时（分钟避开整点，绕开上游 14220 的批处理窗口）。今日生效： -
② 候选模型
按顺序试：第一个是首选，失败换下一个；留空 = 自动（首选模型 + 该区域免费模型，按倍率排序）。 建会话失败（14220）与模型无关，多加候选只是多打几次。
③ 预算
每轮最多等「单轮最长」与「剩余预算」里较小的那个，建会话退避也从预算里扣：预算用完这一轮必出结论（成功 / 失败 / 超时）。 单账号填 0 = 不限制。
进程重启后如果当天还有账号没活跃，立刻补跑一次；旧行为是等到下一个时段，最多再等 12 小时。

本地网络工具

部分客户端（如 Codex App）会宣告 web_search / web_fetch 这类服务端工具，而上游没有对应的执行器：声明送上去，模型看到工具却没有执行器，客户端最后只拿到一句 unsupported call。开启后由本网关代跑——把声明换成自己的同名函数，在本地执行（搜索按 DuckDuckGo → Bing → Wikipedia → Stack Overflow → Google News 的顺序自动轮换，抓页面抓这个 URL）再把结果喂回模型。默认关闭，关闭时声明原样透传，客户端自己声明的搜索工具照常拿到调用。
注意：开启后网关会主动出网抓取模型给出的 URL（字面私网地址与解析进内网的域名都会被挡），且每轮代跑都会多跑一次上游、多消耗该账号的额度；某个搜寻引擎被限流时会自动轮换到下一家，全部不可用才把明确错误交给模型。

剩余用量优先调度

按「剩余用量估算」优先调度：某 (账号 × 模型) 的估计剩余越接近耗尽，分到的请求越多——先把快用完的额度用掉，等它到点重置。剩余不到 30% 开始加权、5% 以内权重最高；没有预算样本、或剩余为 0 / 冷却中的组合不参与。默认关闭。
注意：估算由撞线样本反推的预算与本地用量得出，本身有误差；开启后接近耗尽的账号会明显多接流量，也可能更早撞到上游限额（撞线后该模型停用到上游给出的恢复时刻）。

跨出口回退（国际版 → 国内版）

国际版出口把某个模型限流、当日额度用满、或整池都在冷却时，允许改用同名的国内版出口再试一次。默认关闭——两个出口是两套上游、两套额度、两套积分口径，混用会让「这个 Key 只花国际额度」的部署失去保证。
只对两个出口都提供的模型生效（gpt-* / gemini-* 等国际版独占模型不回退）；方向是单向的，国内版永远不会回退到国际版。出口被显式指定的请求（Key 绑定了出口，或客户端带了 X-Realm / ?realm=）不受影响。

模型额度窗口探针

上游的免费额度窗口按「首次请求」起算：某账号在某模型上被限流（429）后，上游会给出一个重置时刻。开启后，网关会在该时刻到点主动补一个最小请求，把新一轮窗口的计时起点钉在重置那一刻——否则要等到下一次真实请求窗口才开始计时，额度白白空转。默认开启。
注意：探针会真的发一次对话请求，消耗该账号极少量额度（约一条 "Hi"）。到点后若上游仍未放开，最多重试 20 次（每 15 秒一次）后放弃，等下一次 429 重新登记。

出口级瞬时失败退避

传输类失败与 502/503/504 改记在「出口」而不是账号上：同一个出口的账号共用一个计数器，退避是秒级（1 秒起、翻倍、封顶 15 秒、带抖动），任一次成功即清零；账号级熔断（30 分钟起、翻倍到 6 小时）不再被一次链路抖动触发。500 与 401/403/429 仍走原路径。默认关闭。

模型额度定时主动查询

勾选要留意的模型后，网关每 6 小时为每个「账号 + 模型」发一个最小请求，主动确认这条配额线是否已经被打满：打到 429 就立即记该模型的冷却，并把上游给的重置时刻交给上面的「模型额度窗口探针」到点处理；请求通了就说明这条线还没到限额。窗口探针管的是「已经限额之后」，这里管的是「还没限额时先知道」。默认不勾选，勾选后才会定时查询。
注意：每次查询都会真的发一次对话请求，消耗该账号极少量额度；本地一旦有了该「账号 + 模型」的 429 记录，就停止定时查询（改由上面的探针负责），窗口记录消失后自动恢复轮询。

用量聚合保留窗口

用量看板把请求日志按「日桶 + 日桶里的小时子表」预先聚合、落盘成 checkpoint，重启后只读新增的字节。 保留窗口决定这些预聚合能覆盖多久：窗口内的自定义区间直接从桶求和（毫秒级），超出的部分退回整段扫日志（结果一样，只是慢）。
这是「空间换时间」：调大 = checkpoint 变大、写盘更频繁（路由器上 flash 写入慢且费寿命），换更宽的区间走快路径。默认小时层 48 小时、日桶 32 天。

上游响应头超时

单次尝试等上游返回响应头的上限（秒）。拿到响应头之前网关不会向客户端发出任何字节，所以这个值就是客户端要空等的时长：设得比客户端的首字节预算还大时，客户端会先断开（表现为 499 / 首字节迟迟不返回），而网关仍会按这个上限继续换账号重试。默认 120。
调小的代价：上游偶尔确实算得慢的正常请求会被提前判失败、换账号重试，多消耗一次额度。建议不高于客户端的首字节预算。

账号级并发上限

一个上游账号同时最多接几个请求。0 = 不限（默认，跟没这个功能一样）；1 = 一个账号同时只接一个；N = 一个账号最多同时接 N 个。
整个池子能同时接多少 = 账号数 × N（本机 24 个账号：1 → 24 个，3 → 72 个，10 → 240 个）。超出这个数的请求不排队，直接回「每个账号都在忙」，客户端自己重试。
它只防「同一瞬间两个请求压到同一个账号上」（上游按账号+分钟计 token，压一起会回 429、账号被停放）。它治不了「两个开场白相同的会话每轮互换账号」——那种情况每轮都丢缓存，要靠下面的「更稳的会话粘滞键」。
1 和 2–10 的实际区别：只有 1 能保证两个同开场白的会话不会同时撞进同一个号；2 以上只是把总容量放大，两个会话又能同时进同一个号（该撞还是撞）；10 在 24 个账号下基本等于「不限」，除非真的同时有 240 个以上请求。日常两三个会话用不到它，保持 0 即可。

更稳的会话粘滞键 !

会话粘滞（同一段对话每轮回到同一个账号）默认只用「system 提示 + 首条提问」算会话键。两个开场白相同的会话会算出同一个键、共享同一个绑定槽，于是每轮互相覆盖、轮流换账号，缓存每轮归零。开启后把「首条 assistant 回复」也算进键里，两个会话从第 2 轮起各走各的账号。默认关闭，关着时与上游逻辑一字不差。

代价：前缀真的完全相同的会话仍会共用一个账号（那本来就是最优的缓存共享）；开启后前两条消息的哈希变成前三条，正在进行的对话会一次性重新绑定账号（那一轮缓存掉一次）。
